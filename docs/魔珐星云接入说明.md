# 魔珐星云数字人接入说明

> 本项目（电商小二智能客服）对接魔珐星云（Xmov Xingyun）具身智能 3D 数字人的完整说明。
> 所有接口规格均**已核对官方文档** `https://www.xingyun3d.com/developers/52-183`，
> 未确认的部分显式标注 ⚠️ 并集中在可替换点。

---

## 0. 四个必须先知道的架构事实

> 这四点是核实官方文档 + 本机实测后得出的，与"常见想象"不同，直接影响接入方式。

**事实一：数字人的驱动全部在浏览器端。**
官方 JS SDK（`XmovAvatar`）提供 `speak()` / `idle()` / `interactiveidle()` /
`offlineMode()` / `onlineMode()` / `setVolume()` 等方法，**官方未暴露这些能力的后端接口**。
所以本项目**不提供** `/api/avatar/speak` 这类接口 —— 伪造一个必然报错的接口没有意义。

**事实二：官方公开的后端接口只有一个，且与驱动无关。**
`GET https://nebula-agent.xingyun3d.com/user/v1/external/consume_record`（**积分消耗查询**）。
鉴权头为 `X-APP-ID` / `X-TOKEN` / `X-TIMESTAMP`。
→ 它只用来查用量，**不参与数字人驱动**。

**事实三：官方 SDK 的 `appSecret` 是必填参数。**
官方文档「创建实例」的参数表明确 `appSecret` 为**必填**。这意味着：
若要**在浏览器端**初始化 SDK，密钥必须下发到前端。
因此本项目提供 `XMOV_ALLOW_SECRET_TO_CLIENT` 开关 —— 本地演示可开，生产必须关。

**事实四（曾误判，已修正）：不需要 `avatarId`，也不需要请求签名。**
- 官方 SDK 的初始化参数里**没有** `avatarId` / `avatar_id`。角色、音色、表演风格是在
  控制台创建**驱动应用**时选定的，**绑定在 appId 上**，前端不传形象参数。
- 官方文档中「签名」只出现在 `consume_record` 的说明里，**数字人驱动不需要签名**。
  因此签名缺失**不会阻塞**数字人的运行，只影响积分查询接口。

## 3. 配置

### 3.1 `.env`

```dotenv
XMOV_ENABLED=true
XMOV_APP_ID=<你的 App ID>
XMOV_APP_SECRET=<你的 App Secret>
XMOV_GATEWAY_SERVER=https://nebula-agent.xingyun3d.com/user/v1/ttsa/session
XMOV_API_BASE=https://nebula-agent.xingyun3d.com
XMOV_JS_SDK_URL=https://media.xingyun3d.com/xingyun3d/general/litesdk/xmovAvatar@latest.js
XMOV_DEFAULT_AVATAR_ID=default
XMOV_TIMEOUT_SECONDS=15
XMOV_MAX_RETRIES=2
XMOV_ALLOW_SECRET_TO_CLIENT=true
```

### 3.2 配置项说明

| 变量 | 默认 | 说明 |
|---|---|---|
| `XMOV_ENABLED` | `false` | 总开关。关闭时数字人接口返回 **503**，不影响原有功能 |
| `XMOV_APP_ID` | 无 | 控制台「驱动应用 → App 密钥」 |
| `XMOV_APP_SECRET` | 无 | 同上。**绝不可提交到仓库** |
| `XMOV_GATEWAY_SERVER` | 官方示例值 | SDK 初始化必需（官方文档确认） |
| `XMOV_API_BASE` | `nebula-agent.xingyun3d.com` | 后端调用基地址 |
| `XMOV_JS_SDK_URL` | 官方 CDN | **官方确认地址**，前端可直接加载 |
| `XMOV_DEFAULT_AVATAR_ID` | `default` | ⚠️ **官方 SDK 不消费此参数**（见事实四），保留仅作占位，可忽略 |
| `XMOV_TIMEOUT_SECONDS` | `15` | 单次请求超时 |
| `XMOV_MAX_RETRIES` | `2` | 可重试错误的最大重试（指数退避 0.5s→1s→2s，上限 4s） |
| `XMOV_ALLOW_SECRET_TO_CLIENT` | `false` | **仅本地演示**可设 true |

### 3.3 安全建议

1. **`.env` 不入库**：已新增 `.gitignore`。
2. **演示模式是把双刃剑**：`XMOV_ALLOW_SECRET_TO_CLIENT=true` 时，
   任何能访问本服务的人都能拿到 App Secret。**切勿对公网开放**。
   生产环境应改为后端签发一次性 Token（需官方支持）或完全由后端代理。
3. **凭据轮换**：密钥曾在对话明文出现，**建议重新生成**，只写新值到 `.env`。
4. **日志脱敏**：使用 `masked_secret()` / `masked_app_id()`。
5. 生产建议用密钥管理服务（KMS / Vault）注入，而非明文 `.env`。

## 4. 统一接口调用层设计

### 4.1 分层

```
avatar_router.py      ← 参数校验 + 异常 → HTTP 状态码翻译
      ↓
XmovClient            ← 请求构造 / 鉴权 / 超时 / 重试 / 响应解析 / 签名挂载点
      ↓
XmovConfig            ← 配置装载 + 脱敏
XmovError 体系        ← 错误归一化（6 类）
```

### 4.2 设计取舍

| 决策 | 理由 |
|---|---|
| 用**语义化异常**而非返回状态码 | 上层不必到处判断状态码；`retryable` 直接驱动重试决策 |
| **懒加载** `httpx.AsyncClient` | 未启用时不占连接池，零成本 |
| 只对**可恢复错误**重试 | 401/403、签名错误、4xx 参数错误**不重试**；408/429/5xx 才重试 |
| 响应解析兼容**两种命名** | 官方用 `error_code`/`error_reason`，通用风格用 `code`/`message`，都支持 |
| **预留 `_sign()` 挂载点** | 实测证明 `consume_record` 需要签名，但算法未公开；留出接口，拿到算法后一处实现即可 |
| **不伪造驱动接口** | 官方驱动在前端，故提供 `/drive-guide` 说明而非假接口 |

### 4.3 异常 → HTTP 状态码

| 异常 | HTTP | 含义 |
|---|---|---|
| `XmovNotEnabledError` | 503 | 未启用 / 缺凭据 |
| `XmovAuthError` | 502 | 凭据无效 |
| `XmovSignatureError` | **501** | `consume_record` 要求签名，算法待补充 |
| `XmovTimeoutError` | 504 | 超时 |
| `XmovUpstreamError` | 502 | 上游异常 |

## 6. WebSocket 接口：`/ws/avatar/chat`

**用途**：数字人聊天通道。相比 `POST /api/chat`，它多了两项能力：

1. **可打断**：新消息到达时服务端取消上一轮尚未完成的生成，并推 `interrupt`
   让前端立刻停播 —— 用户插话时数字人不会继续说旧内容。
2. **逐条推送**：机器人多条回复可以逐条下发，前端可边收边播。

### 6.1 协议（纯 JSON 文本帧，不传音频）

**客户端 → 服务端**
```json
{"type": "user_text", "sender_id": "u1", "text": "你好", "message_id": "可选"}
```

**服务端 → 客户端**
```json
{"type": "interrupt"}                                                    // 立刻停播
{"type": "user_ack",  "message_id": "..."}
{"type": "bot_text",  "message_id": "...", "index": 0, "text": "...", "object": null}
{"type": "turn_end",  "message_id": "..."}
{"type": "error",     "message": "..."}
```

### 6.2 一轮对话的事件顺序（已实测）

```
interrupt → user_ack → bot_text → bot_text → turn_end
```

### 6.3 关键设计

| 关注点 | 做法 |
|---|---|
| 复用业务逻辑 | 直接调 `DialogueService.process_message()`，与 `POST /api/chat` **完全同源** |
| 引擎开销 | 引擎较重（要读 flow yml），**按连接构建一次**后复用 |
| 数据库会话 | **每轮新建**（与 HTTP 链路一致），避免长连接持有 session |
| 打断的正确实现 | `cancel()` 后**必须 await** 旧任务结束，否则旧回复会和新回复混在一起 |
| 音频 | **不推 PCM**。后端只给文本，声音与口型由前端 SDK 完成（transcript 模式） |

### 6.4 手工测试

```bash
# 前端项目已配置 /ws 代理（vite.config.js），因此从 5173 访问即可
# 后端自检脚本也会覆盖这条通道：
uv run python test/check_avatar_ws.py
```

## 7. 前端集成（`external/customer-service-frontend`）

### 7.1 集成位置

按需求在**对话界面左侧**新增数字人区域，原有聊天功能保持不变：

```
┌─────────────┬──────────────────┬─────────────┐
│  数字人面板  │    对话主区域      │  业务对象    │
│  (320px)    │   (自适应)         │  (370px)    │
│             │                   │             │
│  渲染区      │  消息 / 轮次卡片    │  订单 / 商品 │
│  连接按钮    │  输入框            │             │
└─────────────┴──────────────────┴─────────────┘
```

### 7.2 交互流程

1. 页面加载时数字人**默认不连接**（不消耗积分），面板显示「未连接」+「连接数字人」按钮
2. 点击后：`POST /api/avatar/session` 取凭证 → 动态加载官方 SDK → `new XmovAvatar()` → `init()`
3. 资源下载进度 0→100%，面板实时显示百分比；**到 100% 才允许说话**
4. 连接成功后建立 `/ws/avatar/chat`；此后发送文本消息走 WS，回复自动朗读
5. 再次点击按钮变为「销毁数字人」，释放房间连接

### 7.3 播报策略

- **一次说话一次 speak**：同一轮的多个 `bot_text` 会在 `turn_end` 时**合并成一段**播报，
  避免频繁调用撞上官方「speak 不允许连续多次调用」的限制
- **两次 speak 之间**先调 `interactiveidle()` 切换状态，否则口型会对不上
- 收到 `interrupt` → 立即 `interactiveidle()` 停播并复位 UI 状态
- 消息气泡上的 🔊 按钮 = 重新朗读该条；播放中再点 = 停止

### 7.4 已做的健壮性处理

| 场景 | 处理 |
|---|---|
| 浏览器不支持 WebGL 2.0 | 初始化前预检，直接给出可读提示（不等到 SDK 报错） |
| SDK 报致命错误 | **立即失败**并复位按钮，不再干等 90 秒超时 |
| 网络状态码 50001~50004 | 视为正常状态切换（在线/离线/重试/断开），不当错误处理 |
| 资源下载卡住 | 90 秒超时兜底 |
| 数字人未连接时点朗读 | 提示先连接，不静默失败 |
| 页面刷新/关闭 | `beforeunload` 主动 `destroy()`，避免触发错误码 10005（超出房间并发限制） |
| 硬件加速 | 用官方默认 `default` 自适应，而非写死 `prefer-hardware`（虚拟机/无独显环境更稳） |
| WS 不可用 | 自动回退到 HTTP 链路，功能不中断 |

### 7.5 Vite 代理

`/ws` 必须单独配置并开启 `ws: true`，否则 WebSocket 握手会失败：

```javascript
'/ws': {
  target: 'ws://127.0.0.1:18082',
  ws: true,
  changeOrigin: true,
},
```

## 8. 启动与使用

### 8.1 依赖

`websockets` + `uvicorn[standard]` 已加入 `pyproject.toml`（`uv sync` 自动安装）。
`uvicorn[standard]` 是 WebSocket 协议栈的提供方，**不能只用裸 `uvicorn`**。

### 8.2 启动（3 个终端）

```bash
# ① 数字化人后端（18082）
cd F:\customer-service-backend
uv run python test/check_xmov_config.py      # 可选：先自检
uv run uvicorn api.app:app --host 127.0.0.1 --port 18082

# ② 客服前端（5173）
cd F:\customer-service-backend\external\customer-service-frontend
npm run dev

# ③ 电商业务后端（18081）— 只有需要右侧订单/商品列表时才必须
#    不启动时右侧会显示 JSON 解析错误，属预期现象
```

> ⚠️ **必须用 `uv run`**。直接用系统 Python 会报 `No module named 'fastapi'`，
> 因为依赖装在 uv 管理的虚拟环境里。

### 8.3 打开地址

| 入口 | 地址 | 说明 |
|---|---|---|
| **主界面（推荐）** | `http://127.0.0.1:5173/` | 左侧数字人 + 中间对话，完整功能 |
| 独立演示页 | `http://127.0.0.1:18082/static/avatar_demo.html` | 不依赖 Vite，可单独验证 SDK |

> ⚠️ 必须用 `127.0.0.1` 或 `localhost` 访问。官方明确说明：
> **「目前我们的 SDK 仅支持 localhost 或者 https 访问」**，用局域网 IP 会报错。

### 8.4 操作顺序

1. 打开主界面 → 左侧显示「数字人 · 未连接」
2. 点「连接数字人」→ 等待资源下载到 100%（首次较慢）
3. 在中间输入框提问 → 数字人自动朗读客服回复
4. 试试「新对话」旁边的历史消息 🔊 按钮重新朗读
5. 用完点「销毁数字人」释放连接

## 11. 常见错误速查

| 错误码 | 官方含义 | 本项目对应处理 |
|---|---|---|
| 10001 | 容器不存在 | 检查 `#digital-human-sdk` 是否在 DOM 中 |
| 10002 | Socket 连接错误 | 检查 `gateway_server` 与网络 |
| 10003 | 创建会话失败 | 多为 **appId/appSecret 不对**（见 P9） |
| 10004 | 关闭会话失败 | 一般不影响使用 |
| 10005 | 超出房间并发限制 | 点「销毁数字人」或刷新页面释放连接 |
| 50001/50002 | 进入离线/在线模式 | **正常状态切换，不算错误** |
| 50003/50004 | 网络重试/断开 | 网络波动，SDK 会自行重试 |

> 调试时可在 `initDigitalHuman()` 里把 `enableLogger` 改为 `true`，
> 浏览器控制台会打印 SDK 详细日志。

## 12. 后续建议

1. **先确认 P9**：控制台里是否已创建「驱动应用」并选好角色/音色/表演风格，
   这决定数字人能否真正出现。
2. 若出现「初始化成功但消息发不过去」，去控制台检查该应用的**模型权限**。
3. 长时间无互动时调 `offlineMode()`，可避免积分消耗。
4. **生产环境务必**把 `XMOV_ALLOW_SECRET_TO_CLIENT` 改回 `false`，
   否则任何人都能拿到你的 App Secret。
5. P8 签名算法只影响积分查询，优先级最低。
