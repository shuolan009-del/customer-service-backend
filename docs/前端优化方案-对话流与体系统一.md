## 一、硬约束：现在的接口拿不到任何时间，无法真实"按天分组"

你要的「存放消息的地方根据每天的时间进行对话管理」，我追到了数据源头：

```
GET /api/chat/history  →  HistoryResponse.messages: list[HistoryMessage]

class HistoryMessage(BaseModel):      # api/schemas.py:51
    session_id: str
    role: str          # user / bot
    text: str | None
    object: ChatObject | None
    → 没有 created_at / timestamp，一个时间字段都没有
```

再看后端内部（`domain/state.py`）：

| 层级 | 时间字段 | 现状 |
|---|---|---|
| **Session** | `started_at` / `last_activity_at` / `closed_at`（float 时间戳） | **存在**，但 `load_chat_history` 没往外传 |
| **Turn** | `turn_id` / `user_message` / `bot_messages` | 无时间 |
| **UserMessage / BotMessage** | `sender_id` / `message_id` / `type` / `text` / `object` | 无时间 |

并且 `session_id` 是 `str(uuid.uuid4())`（`domain/state.py:214`），**纯 UUID，无法反推日期**。

**结论：前端无论如何也变不出日期来。** 三条出路，需要你选一条：

### 路线 A —— 前端本地时间轴（零后端改动，可落地，推荐）
- 新增 `utils/timeline.js`：前端给每条消息打本地时间戳，持久化到 `localStorage`
  - 键：`cs-ts:v1:<sender_id>`，值：`{ [message_id]: epochMs }`
  - 发送时（`sendTextMessage` / `sendOrder` / `sendProduct`）与收到 bot 回复时写入
- **本次浏览器产生的消息** → 有准确时间 → 精确分到「今天 / 昨天 / 10月9日」
- **历史接口返回的旧消息** → 无时间 → 统一归入「更早的记录」分组
- 缺陷（必须知情）：仅本机有效；换浏览器 / 清缓存后退化为"更早的记录"

### 路线 B —— 用 `session_id` 做"会话批次"分组（退一步）
- 分组标签从"日期"降级为「本次会话 / 上一次会话」，语义来自后端 Session
- 严格说是**会话维度**，不是你要的**日期维度**
- 优点：100% 真实数据，不依赖本机存储

### 路线 C —— 极微后端改动（需你单独批准）
理论上只需 2 个文件、约 3 行就能让日期分组**真实成立**：
- `api/schemas.py` 的 `HistoryMessage` 加 `started_at: float | None = None`
- `service/dialogue_service.py` 的 `load_chat_history` 透传 `session.started_at`
- ⚠️ 注意粒度：拿到的是**会话级**时间，不是消息级。消息级时间需要给 `Turn` / `UserMessage` 加字段，改动会外溢到对话引擎写入路径 —— **不推荐**

> **A + C 可以叠加**：有 `started_at` 就用真时间，没有就回落本地时间轴。这是最稳的组合。

## 二、目标形态：Turn 分块 → 日期时间轴连续流

### 现状（`WorkbenchView.vue` 952–1084 行）

```
┌─ turn-card ───────────────────────────────┐
│ [Turn 1]  对话轮次                          │
│ ┌ user-section ────────────────────────┐  │
│ │ (头像) 你 · 用户                       │  │
│ │                      [我要退款]        │  │
│ └──────────────────────────────────────┘  │
│ ┌ bot-section ─────────────────────────┐  │
│ │ (头像) 小宝 · 金牌客服                 │  │
│ │ [您好，退款请提供订单号] [也可点右侧]   │  │
│ └──────────────────────────────────────┘  │
└───────────────────────────────────────────┘
┌─ turn-card ───────────────────────────────┐
│ [Turn 2]  对话轮次                          │   ← 又是同样的头像+名字
```

**四个问题：**
1. 每一轮都重复渲染一次「头像 + 名字 + 角色标签」（`.section-header` 在 user 区和 bot 区各一次）
2. Turn 卡片自带边框和背景，把一段连续对话**切成一块一块**
3. `Turn N` / `对话轮次` 是后端内部概念，直接暴露给用户
4. 同一客服连发 3 条话，头像和名字要重复 3 遍（其实只想出现 1 次）

### 目标（连续 IM 流 + 日期时间轴）

```
──────────────── 今天 ────────────────      ← sticky 日期胶囊
                          [我要退款]  ●     ← 用户气泡右对齐
   ●  小宝                                   ← 仅"组首"带头像
      [您好，退款请提供订单号]
      [也可以直接点右侧的订单卡片]            ← 同组气泡紧贴，不重复头像
                              [🔈] [📋]     ← 操作按钮 hover 才出现
──────────────── 昨天 ────────────────
                          [查订单状态]
   ●  小宝
      [您的订单已发货…]
```

### 关键设计决策（逐条可验收）

| # | 决策 | 说明 |
|---|---|---|
| D1 | **按自然日分组** | 分组键 = `yyyy-MM-dd`；`今天` / `昨天` / `10月9日` / 跨年补 `2025年10月9日` |
| D2 | **日期分隔用 sticky 胶囊** | 滚动时吸顶，替代现在的 `.history-divider`（"以上为历史消息"） |
| D3 | **头像去重** | 同一 sender 连续消息只在**首条**显示头像；后续气泡左侧留 38px 对齐 |
| D4 | **气泡间距分级** | 同组内 6px，跨组（换人说话）18px |
| D5 | **去掉 Turn 卡片外壳** | 删除 `.turn-card` 边框/背景，消息直接排在流里 |
| D6 | **操作按钮降噪** | `🔈` `📋` 由"每条常驻"改为 hover / focus-within 显现；触摸设备常显（`@media (hover: none)`） |
| D7 | **新增"回到最新"浮标** | 不在底部时显示「↓ N 条新消息」，点击滚到底（复用 `useChat.unreadCount`） |
| D8 | **对象卡片保留卡片形态** | 订单/商品卡作为流内一条消息，宽度与气泡列对齐，不参与气泡分组 |
| D9 | **保留三栏布局** | 左 320（数字人）/ 中弹性（对话）/ 右 370（业务对象），`--wb-left/right/gap` 令牌不变 |
| D10 | **welcome 态保留** | `turns` 为空时的欢迎卡保留，只去掉里面 emoji 换成 SVG 图标 |
