### 本轮核查结论（第一次摸清的几件事）

1. **重构确实只做了一半**：`useChat 359 / useAvatar 355 / useAvatarWs 110 / useSidebar 55 /
   useClipboard 52` 共 **931 行 composable 零视图引用**（`useAvatarWs` 仅被 `useAvatar` 引，
   `useChat` 无外部入口）。工作台里用手写代码把同一套逻辑**又实现了一遍**：
   Turn 分组、WS 插话打断、TTS 状态机。**但缺两个能力**：WS 指数退避重连（工作台断了不重连）、
   未读计数 / scrolledToBottom（工作台完全没有）。
2. **工作台是唯一遗留孤岛**：2509 行；样式块 1276 行（1233–2509）；仅用 `Skeleton`/`EmptyState`
   两个 UI 原语；图标仍 emoji（🔄/🔈/📋/📦/🛍️）；**引用旧令牌别名 92 处**
   （`--color-surface`×22 / `--color-border`×19 / `--ease-out-expo`×15 / `--color-border-light`×11 /
   `--color-border-strong`×9 / `--color-surface-hover`×3 / `--color-bg-surface`×2）
   → 这是 `design-tokens.css` 末尾 Legacy 别名层**删不掉的唯一原因**。
3. **布局 bug（新发现）**：`.avatar-panel` 用 `calc(100vh - 48px)`，`.chat-card`/`.sidebar` 用
   `calc(100vh - var(--shell-h) - 48px)` → **左栏比中右两栏高 56px**，三栏顶/底对齐错位。
   位置：`WorkbenchView.vue` 第 1283-1284 行 vs 1256-1257 行。
4. **死代码新发现**：`.history-divider`（「以上为历史消息」）**永远不会渲染** ——
   `appendMessage` 的 `role === 'divider'` 分支只在 `setHistoryMessages` 可能命中，
   而后端 `HistoryMessage.role` 只会是 `user`/`bot`。
5. **⚠️ 日期分组的硬约束（决定性发现）**：
   - `api/schemas.py:51` 的 `HistoryMessage` = `session_id / role / text / object`，**无任何时间字段**
   - 时间戳只存在于 **Session 级**（`domain/state.py:24-26` `started_at` / `last_activity_at` / `closed_at`），
     且 `load_chat_history` 不往外传；**Turn / UserMessage / BotMessage 全部无时间字段**
   - `session_id` 是 `str(uuid.uuid4())`（`domain/state.py:214`），**无法反推日期**
   → 结论：**不改后端就无法真实按天分组**。方案给了三条路线（A 前端 localStorage 时间轴 /
     B 用 session_id 做会话批次分组 / C 极微后端改动，仅 2 文件约 3 行，需用户单独批准）。
   A+C 可叠加。
6. 设置页 `cs-prefs`（`defaultSenderId` / `autoConnectAvatar` / `reduceMotion`）**全仓无人读取**，
   是死设置；工作台 `sender_id` 为页面私有 ref，与会话记录页 / 设置页互不同步。
