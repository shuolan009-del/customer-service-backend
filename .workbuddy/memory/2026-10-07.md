## 数字人选型咨询（仅调研，未改代码）

**背景**：用户问「我的项目使用什么数字人比较合适、哪家比较好」。先读了项目代码确认现状：
- 后端是 FastAPI + `POST /api/chat`（`api/routers/chat_router.py`），请求体 `text` 或 `object`（订单/商品聚焦），
  返回 `messages[]` 文本消息 —— **纯文本接口，无任何音频/视频/形象字段**。
- 处理链路 `DialogueService → DialogueEngine`，三条轨道：Task 流程 / Knowledge / ChitChat。
- 依赖里**没有任何 TTS / ASR / 音频 / 形象相关库**（grep tts|asr|audio|avatar 全项目 0 命中，排除 external/）。
- 结论：项目**没有数字人层**，缺的是 ASR + TTS + 形象驱动，数字人是「新增一层」，不是「换模型」。

**给出的选型结论（分档）**：
1. 有 GPU + 要私有化 → **OpenAvatarChat**（HumanAIGC-Engineering，模块化 handler，可把 LLM 换成自己的
   `/api/chat`，4090 实测端到端 2.2s，6–10GB 显存）；口型可换 **LiveTalking**（100–500ms 口型层、
   支持打断与空闲动作，最贴「数字人客服」形态）。
2. 无 GPU / 要省心 / 团队无音视频经验 → **腾讯云智能数智人**（API+SDK 最成熟，租赁 50 元/月/形象起，
   2D 小样本定制约 1000 元/个起，云渲染交互 3500 元/月/路）。
3. 电商直播方向 → 火山引擎（绑抖音，≈500ms）/ 百度曦灵（政企，2999 元/月起）。

**关键架构建议**：数字人只做表现层外壳，**不改 `/api/chat` 的入参出参**；形象驱动只需
`audio + text 时间戳`，而现有 `BotMessage` 缺 item 级文本切分（`turn_plan.jinja2` 是单段文本），
若要做高质量口型需要给响应加 item 粒度。音频格式建议 16kHz 单声道 PCM 分块对齐 20ms 帧。

**注意**：以上为调研结论，未做任何代码修改。延迟数字（2.2s / 135ms 等）多来自官方或第三方实测，
非本机验证，落地前需实测。
